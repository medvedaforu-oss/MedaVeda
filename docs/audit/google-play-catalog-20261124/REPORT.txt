3. IMPLEMENTATION REVIEW

No confirmed local catalog defect causing 403. Current sync-play-catalog v7 and
playCatalog.ts match local source byte-for-byte. Google helper differs only by a
local optional ExternalTransaction.testPurchase type member, irrelevant to catalog

The request matches the current official API contract:
- PATCH uses lowercase /applications/{package}/onetimeproducts/{productId}.
  GET/list use camel-case /applications/{package}/oneTimeProducts[/{productId}].
- Product is the top-level JSON body, with exact package/SKU, en-US listing and
  purchaseOptions. updateMask=listings,purchaseOptions; allowMissing=true;
  regionsVersion.version is a required query parameter. On creation Google
  ignores updateMask. Internal input-only body omits output-only state/version.
- buy is a valid purchase option identifier. buyOption.legacyCompatible=true,
  multiQuantityEnabled=false; no rent option; only IN/AVAILABLE. INR 1.00 is
  serialized exactly as currencyCode=INR, units="1", nanos=0. This serialization
  is valid Money syntax, not evidence that the price is commercially permitted.
- Version allowlist explicitly requires 2022/02. Google's public table still
  lists this historical version; RegionsVersion documents old-version support.
  The actual configured production value was not read. Do not change it blindly.
- Activation uses POST oneTimeProducts/{sku}/purchaseOptions:batchUpdateStates
  with requests[].activatePurchaseOptionRequest and exact package/SKU/buy.
  ACTIVE is the purchase-option state; there is no separate product state field.
- Independent GETs follow creation and activation. verifiedBuyOption rejects a
  wrong identity, ambiguous/multiple option, rent/multi-quantity, inactive option,
  duplicate IN row, unavailable IN config, wrong currency or inexact price. Only
  then does the existing worker call finish_play_price_sync to write a tier.
