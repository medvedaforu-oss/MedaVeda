DESCRIPTION
  Deploy a Function to the linked Supabase project.

TARGET
  Remote only. Uses the linked project; pass --remote=<ref|branch> for another.

USAGE
  supabase functions deploy [flags] [<Function name...>]

ARGUMENTS
  Function name... string  Names of Functions to deploy. Deploys all if omitted. (optional)

FLAGS
  --remote[=<ref|branch>]    Target another project: --remote=<ref|branch>. Defaults to the linked project.
  --no-verify-jwt            Disable JWT verification for the Function.
  --use-api                  Bundle functions server-side without using Docker.
  --import-map string        Path to import map file.
  --prune                    Delete Functions that exist in Supabase project but not locally.
  --jobs, -j integer         Maximum number of parallel jobs.

GLOBAL FLAGS
  --help, -h                                                          Show help information
  --version, -v                                                       Show version information
  --wizard                                                            Start wizard mode for a command
  --completions <bash|zsh|fish|sh>                                    Print shell completion script (choices: bash, zsh, fish, sh)
  --log-level <all|trace|debug|info|warn|warning|error|fatal|none>    Sets the minimum log level (choices: all, trace, debug, info, warn, warning, error, fatal, none)
  --output-format choice                                              Output format: text (default), json, or stream-json (NDJSON) (choices: text, json, stream-json)
  --output, -o choice                                                 output format of status variables (choices: env, pretty, json, toml, yaml, table, csv)
  --profile string                                                    use a specific profile for connecting to Supabase API
  --debug                                                             output debug logs to stderr
  --workdir string                                                    path to the directory containing your supabase/ folder; used exactly as given, with no ancestor directory search (defaults to searching upward from the current directory)
  --experimental                                                      enable experimental features
  --network-id string                                                 use the specified docker network instead of a generated one
  --yes                                                               answer yes to all prompts; hosted changes only accept this flag or SUPABASE_YES exported in your shell, never supabase/.env or another .env file
  --dns-resolver choice                                               lookup domain names using the specified resolver (choices: native, https)
  --agent choice                                                      Override agent detection: yes, no, or auto (default auto) (choices: auto, yes, no)

EXAMPLES
  # Deploy a single function to the linked project
  supabase functions deploy hello-world

  # Deploy all local functions to a specific project
  supabase functions deploy --remote=abcdefghijklmnopqrst

PERMISSIONS
  Scoped access token:
    Required:
      edge_functions_write
    Required with --prune:
      edge_functions_read
    May be required (without --use-api or without --no-verify-jwt):
      edge_functions_read
    May be required:
      projects_read
      branching_development_read for a preview branch
        or branching_production_read for the main branch
    Optional (command still runs without these):
      project_admin_read
