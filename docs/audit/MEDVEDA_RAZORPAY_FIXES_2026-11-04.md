**Flow and preserved security checks**

Buy Now → server quote → authenticated create-order → service-only pricing and stored amount → Razorpay INR order → checkout → signature verification or account-owned recovery → provider payment/order lookup → captured/currency/order/amount checks → durable capture → locked SQL settlement → stored purchase → secure Notes URL authorization → My Purchases. Android currently stops at the initial disabled guard; declared native requests also remain rejected by create-order before writes. Neither safeguard was removed.

Actual HMAC code and handler tests reject missing/forged signatures, wrong owner/order/currency/amount and authorized-but-uncaptured payments. SQL and existing suites cover one payment/purchase per order, wallet/referral accounting, full/partial refunds, disputes and out-of-order/duplicate webhooks. Provider HTTP/Auth/Storage are mocked where indicated; local SQL uses synthetic service-boundary capture inputs. These tests do not establish hosted capture, webhook delivery, merchant payouts or native UPI behavior.
