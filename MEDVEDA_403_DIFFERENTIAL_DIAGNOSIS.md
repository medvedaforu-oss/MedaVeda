## C. Request correctness verdict

The current [convertRegionPrices reference](https://developers.google.com/android-publisher/api-ref/rest/v3/monetization/convertRegionPrices) specifies POST to `https://androidpublisher.googleapis.com/androidpublisher/v3/applications/{packageName}/pricing:convertRegionPrices`, with a `price` Money object representing a tax-exclusive input price and Android Publisher OAuth scope. The local diagnostic matches at `handler.ts:45–58`; catalog matches at `playCatalog.ts:59–62`. No additional required request field is documented.

Diagnostic body: `{"price":{"currencyCode":"INR","units":"1","nanos":0}}`. Catalog derives integer paise via `playCatalog.ts:14–18`, then `units = String(Math.floor(cents / 100))`, `nanos = (cents % 100) * 10_000_000` at `:59–60`. For ₹199.99 this gives `"199"` and `990000000`; positive supported inputs keep nanos between 0 and 990,000,000. This matches the [Money schema](https://developers.google.com/android-publisher/api-ref/rest/v3/Money): currency code, string whole units, integer billionths with consistent signs. **No confirmed malformed conversion body.** Business price eligibility/minimums are distinct from schema correctness and are not verified by this inspection.

**400 versus 403:** Google's canonical mapping assigns invalid arguments to HTTP 400, authentication failures to 401, and permission denial to 403. It explicitly says a permission denial does not establish that the request is otherwise valid or its target exists. Thus malformed input is documented as 400 when diagnosed as INVALID_ARGUMENT; the method reference does not promise validation order or an exhaustive method-specific error list. A 403 cannot prove body validity, but it is not evidence that INR serialization caused the denial. System preconditions can also map to 400. [Google canonical error codes](https://docs.cloud.google.com/vision/docs/reference/rest/v1/Code).

**Separate confirmed path observation:** read uses `/oneTimeProducts/` (`playCatalog.ts:42`), PATCH uses `/onetimeproducts/` (`:80`), activation uses `/oneTimeProducts/` (`:86`). These spellings look inconsistent but match the respective current [list](https://developers.google.com/android-publisher/api-ref/rest/v3/monetization.onetimeproducts/list) , [PATCH](https://developers.google.com/android-publisher/api-ref/rest/v3/monetization.onetimeproducts/patch), and [activation](https://developers.google.com/android-publisher/api-ref/rest/v3/monetization.onetimeproducts.purchaseOptions/batchUpdateStates) contracts. Do not normalize their casing as a proposed fix. The requested matrix's lowercase listing path must be corrected to `/oneTimeProducts`.
